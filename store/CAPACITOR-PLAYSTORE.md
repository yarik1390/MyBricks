# BricksVault → Google Play (Capacitor + Play Billing) — full runbook

Step-by-step from the repo to a **signed `.aab`** on Google Play, with the
**BricksVault Pro** subscription sold through **Google Play Billing** (via
RevenueCat). This is the path the repo is built for — **not** PWABuilder/TWA,
which can't drive the RevenueCat native plugin.

> **What's already done in the repo** (you don't touch these):
> - Billing client `public/js/lib/revenuecat-native.js` (entitlement `BricksVault Pro`).
> - Me-tab Upgrade / Restore / Manage buttons (native only; web keeps Patreon).
> - Server webhook `POST /api/revenuecat/webhook` — flips `is_supporter` (source of truth).
> - `store/capacitor.config.json` (appId `app.bricksvault`, appName `BricksVault`).
> - CI injects `window.RC_PLAY_BILLING_KEY` into the deployed `env.js` from a secret.
>
> Everything below is account/machine work only you can do.

Legend: **[ONCE]** one-time setup · **[EACH]** repeat on every release.

---

## 0. Prerequisites
- [ ] **Google Play Console** account — **$25 one-time** (https://play.google.com/console).
- [ ] A machine with **Node 20+**, **Java 17**, and **Android Studio** (Windows/Mac/Linux all fine — Android does *not* need a Mac; only the later iOS build does).
- [ ] A **RevenueCat** account (free tier is enough to start) — https://www.revenuecat.com.
- [x] **App id is decided and locked: `app.bricksvault`** — matches the app you created in Play Console. It is used consistently in `capacitor.config.json`, `android/`, `assetlinks.json`, and must be used in RevenueCat too. **Once published you can never change it.**

---

## 1. [ONCE] Local Capacitor project
Run from the **repo root** (`/…/MyBricks`).

```bash
# 1a. Install Capacitor core + Android, push, and RevenueCat plugins.
npm i @capacitor/core @capacitor/cli @capacitor/android
npm i @capacitor/push-notifications
npm i @revenuecat/purchases-capacitor @revenuecat/purchases-capacitor-ui

# 1b. Put the Capacitor config at the repo root (it lives in store/ in git).
cp store/capacitor.config.json ./capacitor.config.json

# 1c. Add the native Android project. webDir is "public" and is bundled into
#     the app, so the shell and guest features start without network access.
npx cap add android

# 1d. Link the native plugin code into the Android project.
npx cap sync android
```

**Verify the plugin names** — the bridge in `revenuecat-native.js` registers
plugins by string name. Open
`node_modules/@revenuecat/purchases-capacitor/dist/esm/index.js` and look for
the `registerPlugin('…')` call. It should be **`Purchases`**; the UI plugin in
`@revenuecat/purchases-capacitor-ui` should be **`RevenueCatUI`**. If either
differs, fix the two constants at the top of
`public/js/lib/revenuecat-native.js` (`PURCHASES_PLUGIN`, `UI_PLUGIN`) and
redeploy Pages.

> **`.gitignore`:** the generated `android/` folder and `capacitor.config.json`
> at root don't need to be committed — they're regenerated by `cap add`/`cap
> sync`. Keep your **keystore** (step 5) out of git no matter what.

## 2. [ONCE] Create the app in Play Console
1. Play Console → **Create app**. Name **BricksVault**, default language, **App**, **Free** (the app is free; the *subscription* is the paid part).
2. Complete the **App content** section stubs Google requires before any release:
   - **Privacy policy URL:** `https://bricksvault.app/privacy.html`
   - **Data safety** form — answers drafted in `store/listing.md`.
   - **Content rating** questionnaire (IARC).
   - **Target audience**, **Ads** (declare none if true), **Government apps** (no).
3. Note your **package name** must equal `app.bricksvault`.

---

## 3. [ONCE] Create the Play Billing products
Play Console → **Monetize → Products**.

- **Subscriptions** → create `yearly` and `monthly` base plans (auto-renewing).
- **In-app products** → create `lifetime` (one-time, non-consumable) if you want a lifetime tier.

Set prices, then **Activate** each. Product IDs are up to you but keep them
memorable — you'll attach them in RevenueCat. (RevenueCat abstracts these, so
the app code never hard-codes product IDs.)

**License testers** (buy without being charged): Play Console → **Setup →
License testing** → add the Google accounts that will test. Also add those
accounts as testers on your **Internal testing** track (step 7).

---

## 4. [ONCE] RevenueCat wiring
1. RevenueCat dashboard → **new Project** → add an **App → Google Play**.
2. It asks for a **Google Play service-account JSON** with billing permissions.
   In Google Cloud / Play Console, create a service account, grant it
   **Financial data / Manage orders** in Play Console → **Users & permissions**,
   download the JSON, upload it to RevenueCat.
3. **Entitlement:** create one with identifier **exactly `BricksVault Pro`** —
   this must match `ENTITLEMENT_ID` in `revenuecat-native.js`. ⚠️ This is the
   single string that has to line up on both sides.
4. **Products:** import `yearly`, `monthly`, `lifetime` from Play; **attach all
   three to the `BricksVault Pro` entitlement**.
5. **Offering:** build one named **`default`** with a package per product. The
   paywall reads the current offering.
6. **Paywall:** design it in RevenueCat (Paywalls tab). `presentProPaywall()`
   calls `presentPaywallIfNeeded` for the `BricksVault Pro` entitlement, so a
   configured paywall is required for the button to show anything.
7. **API key:** Project → **API keys** → copy the **Google** *public* key. It
   starts with **`goog_`**. (A `test_…` key is a *Web Billing* key and will
   **not** drive Play Billing — don't use it here.)

---

## 5. [ONCE] Wire the keys into the app + server
Two secrets, both set in **GitHub → repo → Settings → Secrets and variables → Actions**:

| Secret | Value | Used by |
|---|---|---|
| `RC_PLAY_BILLING_KEY` | the `goog_…` public key | CI injects it into the deployed `env.js`; the app reads `window.RC_PLAY_BILLING_KEY` |
| `REVENUECAT_WEBHOOK_AUTH` | any long random string you choose | Worker verifies the `Authorization` header on `POST /api/revenuecat/webhook` |
| `ANDROID_GOOGLE_SERVICES_JSON_BASE64` | base64 of Firebase `google-services.json` | Android build configures FCM device registration |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Firebase Admin service-account JSON | Worker sends native alerts through FCM HTTP v1 |
| `ANDROID_APP_LINK_SHA256` | Play App Signing SHA-256 fingerprint | Pages publishes a verified App Link so Google login returns to the app |

Then in **RevenueCat → Integrations → Webhooks**:
- **URL:** `https://brickvault-api.zhydenko.workers.dev/api/revenuecat/webhook`
- **Authorization header:** the *same* value you put in `REVENUECAT_WEBHOOK_AUTH`.

Push any commit (or re-run the deploy workflow) so CI rebuilds `env.js` with the
key. Verify: open `https://bricksvault.app/env.js` in a browser — you
should see the `window.RC_PLAY_BILLING_KEY = 'goog_…'` line.

> The Capacitor app bundles `public/`. The Android workflow injects the RevenueCat
> key before `cap sync`; the Pages workflow injects it separately for the web app.

Create a Firebase Android app with package `app.bricksvault`, download
`google-services.json`, and base64-encode it into
`ANDROID_GOOGLE_SERVICES_JSON_BASE64`. Create a Firebase service account with
Cloud Messaging permission and store its complete JSON as
`FIREBASE_SERVICE_ACCOUNT_JSON`. Do not commit either credential file.

## 6. [ONCE] App signing (keystore)
Google **Play App Signing** holds the real key; you upload with an **upload key**.

```bash
keytool -genkey -v -keystore bricksvault-upload.keystore \
  -alias bricksvault -keyalg RSA -keysize 2048 -validity 10000
```

Store the keystore file + passwords in a password manager — **losing it blocks
future updates**. Keep it out of git.

---

## 7. [EACH] Build the signed `.aab`
1. Bump the version for every upload: in `android/app/build.gradle` set
   `versionName "1.0.0"` and increment `versionCode` (integer, must go up each
   upload: 1, 2, 3…). (Matches `store/twa-manifest.json` `appVersionName 1.0.0`.)
2. Run `npm run android:assetlinks` with `ANDROID_APP_LINK_SHA256` set, then
   `npm run android:preflight`. Run `npx cap sync android` (picks up bundled
   web/plugin changes), then
   `npx cap open android` to open Android Studio.
3. Android Studio → **Build → Generate Signed Bundle / APK → Android App
   Bundle** → choose your `bricksvault-upload.keystore` → **release** → produces
   `android/app/release/app-release.aab`.
4. Play Console → **Testing → Internal testing → Create release** → upload the
   `.aab` → add release notes → **Save → Review → Start rollout to Internal
   testing**. First upload also asks you to **enrol in Play App Signing** — accept.

---

## 8. [EACH] Test the purchase (no real charge)
1. On a test device signed in with a **license-tester** account, join the
   internal-testing link (Play Console gives you an opt-in URL).
2. Install BricksVault from Play (the tester track), open **Me → Upgrade to
   Pro** → the RevenueCat paywall appears → buy with the tester account (shows
   "Test card, always approves").
3. Confirm the entitlement flips: the Me tab should show **BricksVault Pro**.
   Cross-device confirmation comes from the webhook flipping `is_supporter`
   server-side — check the RevenueCat **Customer** view and your D1
   `is_supporter` for that user.
4. Test **Restore** (reinstall → Restore purchases) and **Manage subscription**
   (opens RevenueCat Customer Center).

---

## 9. [ONCE→EACH] Store listing + go to production
1. **Main store listing:** short & full description, icon, feature graphic
   **1024×500**, 2–8 phone screenshots — drafts in `store/listing.md` and
   `store/CHECKLIST.md` §4.
2. Make sure **Data safety**, **content rating**, **target audience** (step 2)
   are all green.
3. Promote the tested release: **Production → Create release** (or promote the
   internal build) → roll out. First production submission triggers Google
   **review** (hours to a few days).

## Troubleshooting

| Symptom | Cause → fix |
|---|---|
| Me tab shows **Patreon**, not "Upgrade to Pro" | Not running in the native app, or `window.Capacitor` missing. `isNativeBilling()` is false → confirm you launched the installed **app**, not the website. |
| Upgrade button does nothing / "unavailable" | `RC_PLAY_BILLING_KEY` not in the deployed `env.js` (check `…/env.js`), or the `default` Offering/Paywall isn't configured in RevenueCat. |
| Paywall shows but purchase fails | Product not **Active** in Play, tester account not in **License testing**, or the app's `versionCode` was never uploaded to a track (Play needs an uploaded build to enable billing). |
| Plugin not found at runtime | Plugin registration name mismatch — re-check `Purchases`/`RevenueCatUI` against the installed plugin and the two constants in `revenuecat-native.js`; re-run `npx cap sync android`. |
| Purchase succeeds but `is_supporter` stays false | Webhook not firing — check the RevenueCat webhook URL + that its Authorization value equals the `REVENUECAT_WEBHOOK_AUTH` Worker secret. |
| "You need to use a different version code" | Bump `versionCode` in `android/app/build.gradle`; every upload must be strictly higher. |

## What you do NOT need
- No native rewrite — the Capacitor shell reuses the existing PWA.
- No separate codebase for iOS — same project, `cap add ios` later.
- No PWABuilder/TWA — it can't run the RevenueCat native plugin.
- `assetlinks.json` is required for the Google OAuth return path. It must include
  the **Play App Signing** certificate fingerprint, not only the local debug or
  upload-key fingerprint.
