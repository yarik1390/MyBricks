# BricksVault (MyBricks): agent working guide

This file is the entry point for the Hermes agent (Hermes loads `.hermes.md`
first and then skips `AGENTS.md`/`CLAUDE.md`, so everything an agent must not get
wrong is repeated here in short form). Claude Code reads `CLAUDE.md`; both agents
share `AGENTS.md` (full reference) and `HANDOFF.md` (live state + coordination).

## Start of every session

1. `git fetch origin && git checkout main && git pull` and read `HANDOFF.md`.
2. Check open PRs and the "In flight" table in `HANDOFF.md`. Do not edit files
   another agent has claimed there; pick other work or ask the owner.
3. Add your own row to "In flight" before you start changing files (see the
   protocol in `HANDOFF.md`).
4. Read the `AGENTS.md` section for the area you touch (it is about 68 KB, so
   read sections on demand instead of all at once): section 4 data model and
   valuation, 5 API, 6 frontend, 7 deploy and hard constraints, 8 secrets (names
   only), 9 conventions, 10 gotchas, 11 changelog.

`HANDOFF-sources.md` and `PRICING-AUDIT.md` are older, topic-specific notes;
their branch rules ("work on main, no PRs") are out of date.

## What this is

BricksVault is a mobile-first PWA and Android app (Capacitor) for LEGO
collectors: owned sets, market value and ROI, wishlist with price-drop alerts,
scanner, public profiles. Live at https://bricksvault.app. The Play Store app
bundles `public/` inside the APK, so web changes reach phones only through a new
Android build.

- Backend: Cloudflare Worker, TypeScript, Hono, in `worker/src`
  (`routes/`, `jobs/`, `lib/`, entry `index.ts`).
- Database: Cloudflare D1 (SQLite), binding `DB`.
- Auth: Supabase JWT verified in `worker/src/auth.ts` (`requireMember`).
- Frontend: vanilla JS SPA with hash routing in `public/js`, no framework.
- Android: `android/` + `capacitor.config.json`; `versionName` is derived from
  `public/sw.js` `VERSION` (v659 -> 1.0.659).

## How changes ship (actual practice)

1. Branch from `main` (one branch per task, e.g. `hermes/<topic>` or
   `claude/<topic>`). Never push straight to `main`.
2. Run every gate locally before pushing (the deploy runs all five; running only
   some has broken deploys before):
   ```bash
   npm ci && npm --prefix worker ci
   npm test                          # root: UI strings, i18n, scripts/__tests__, frontend tests
   npx biome lint
   cd worker && npx tsc --noEmit && npx vitest run
   ```
   If a UI string changed: `node scripts/harvest-ui-strings.mjs --write`.
3. Open a PR to `main`. PR checks: `checks` (pr-checks.yml), `smoke`
   (e2e-smoke.yml), `a11y`. Drive them green; never skip, disable or quarantine
   a test to get green.
4. Merge with a merge commit titled `Merge #N: <title>` once green. The owner
   has authorised agents to merge their own green PRs.
5. After the merge, verify all of these on `main`:
   - "Deploy Brickvault" (deploy-worker.yml, about 9 min; runs only when
     `worker/**` or `public/**` changed),
   - "Build Android (.aab)" (only when `public/**`, `android/**` or
     `package*.json` changed; uploads to Play internal testing),
   - "e2e-smoke" on the merge commit,
   - `curl -s https://bricksvault.app/sw.js | grep VERSION` shows your new
     version, and one changed JS file on the live site contains your change.
6. Update `HANDOFF.md` (remove your "In flight" row, add a line to "Recently
   shipped") in the same PR or a follow-up.
7. Report to the owner in plain language: what users will see on each screen
   (e.g. Vault, Discover, Retiring soon, Coming soon, Set page), and remind them
   to fully close and reopen the app (or update from Play) to get it.

## Hard constraints (each of these has broken production before)

- **Public repository.** Never commit secrets, API keys, tokens, emails,
  account IDs, personal or legal notes. Secret names only (see `AGENTS.md` §8).
- **D1 schema:** no `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` (D1 rejects it).
  New column = add it to the `CREATE TABLE` in `worker/schema.sql` AND one
  single-line `ALTER TABLE ... ADD COLUMN ...;` in `worker/schema_migrate.sql`.
  Update `worker/src/test-schema.ts` / test fixtures if tests touch it.
- **`lego_sets` is at D1's 100-column cap.** Any new per-set field goes in a
  side table keyed by set, never a new `lego_sets` column. Bulk queries also
  must not return more than 100 columns.
- **D1 limits:** at most 100 bound params per query, 30 s per query. Avoid
  non-indexable joins across the catalog (see `AGENTS.md` §10).
- **Crons:** use day names (`0 4 * * SUN`, not `0`). Every cron in
  `worker/wrangler.toml` `[triggers]` needs an exactly matching `case` in
  `scheduled()` in `worker/src/index.ts` (a test checks parity).
- **Service worker:** bump `VERSION` in `public/sw.js` on any change under
  `public/`, and keep `STATIC_ASSETS` in sync with `public/js` (a test fails
  otherwise). Before merging, re-check `main`'s VERSION: parallel PRs often pick
  the same number and git merges identical bumps silently. If that happens,
  bump again.
- **Routes:** every route uses `requireMember` except the deliberate public
  ones listed in `CLAUDE.md`. Be explicit about middleware on new routes.
- **Soft deletes:** `user_collection` rows set `deleted_at`; every read filters
  `deleted_at IS NULL`.
- **Money:** store values in USD; convert only at render (`public/js/utils.js`).
- **External integrations are non-fatal:** fetchers return `null` on failure and
  callers fall back. Wrap calls so they record quota and integration health.
- **AI endpoints honour BYOK headers** (`X-Gemini-Key`, `X-OpenAI-Key`) and the
  `rate_limits` table.
- **BrickEconomy data** must not feed the value model and must not be shown to
  users. Do not relabel it as the app's own prices.
- **Workflow files:** the Claude GitHub app cannot push `.github/workflows/`
  changes; if a task needs one, say so to the owner.

## Frontend rules

- Top-bar back arrows must not bind their own click handler. The global
  handler in `public/js/components/collector-shell.js` calls `goBackOr`; use
  `data-bv-back-fallback` for a custom fallback route.
- Desktop-only layout lives in `public/desktop.css` and
  `public/js/lib/desktop.js`. Leave phone layout untouched when doing desktop
  work.
- i18n: add strings to `public/js/locales/en.js` first; placeholders must match
  English in every locale. Ukrainian is a first-class locale.
- Pure, no-DOM helpers go in `public/js/lib/pure.js` with tests in
  `public/js/__tests__/`.
- The "taste-skill" design overhaul was reverted at the owner's request; do not
  reapply it. Design changes need the owner's approval (mockups first).
- Route names differ from labels: Catalog is `#/add`, Scan is `#/pile`.

## Working next to another agent

- Claude and Hermes both work on this repo, often at the same time. The
  coordination rules and the "In flight" table are in `HANDOFF.md`. Keep PRs
  small, rebase on `main` before merging, and prefer new files over edits to
  hotspots (`worker/src/index.ts`, `public/js/views/portfolio.js`,
  `public/app.css`, `public/sw.js`).
- Do not force-push or rewrite another agent's branch. Do not close another
  agent's PR.
- Ask the owner before anything irreversible or outward-facing: production
  data changes, bulk deletes, Play Store releases or rollouts, emails to users,
  changing secrets or paid services.
